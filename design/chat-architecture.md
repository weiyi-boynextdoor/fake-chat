# 聊天界面与共享数据结构

## 目标

首次启动不创建任何角色或聊天。角色由用户创建，第一个角色自动成为当前身份。当前先实现微信风格，后续增加其他 App 的聊天界面。

## 代码分层

- `App/`：应用入口、平台列表和会话页面路由。
- `Models/`：角色、消息、会话、平台及持久化快照，不依赖 SwiftUI。
- `Storage/`：共享聊天操作与本地持久化，不包含微信布局或配色。
- `Features/Characters/`：共享角色管理和角色创建。
- `Features/Conversations/`：共享聊天对象选择与发起聊天流程。
- `Common/`：共享聊天详情、消息行、媒体查看器、头像组件及中英文文案选择。
- `Platforms/WeChat/`：微信对话列表及视觉样式。
- `Platforms/Douyin/`：抖音对话列表及个人资料入口。

## 平台边界

会话使用 `ChatPlatform` 记录所属平台；当前仅声明已实现的微信。查询及复用会话时同时匹配平台和参与者，避免后续不同平台之间混用聊天记录。

新增平台时增加对应枚举值、平台界面目录及路由分支。角色、消息、存储与角色辅助界面继续复用，各平台分别负责自己的对话列表和聊天布局。暂不为了未实现的平台建立通用布局协议。

## 空状态与兼容

- 当前身份可以为空，不使用随机 ID 或数组首项强制兜底。
- 无角色时提供创建入口；只有一个角色时引导创建聊天对象。
- 第一个角色自动选中，后续创建角色保留当前身份。
- 保留已有本地记录；旧版会话缺少平台字段时按微信解码。此前保存的示例记录不会自动删除，以免误删用户编辑过的内容。
- 保存的当前身份无效时选择第一个已有角色，无角色时保持为空。
- 本地读取失败时保留原始数据，阻止新内容覆盖损坏记录并显示提示。

## 单方删除会话

共享会话保留消息原始顺序，使用参与者各自的 `deletedForCharacterIDs` 与 `clearedMessageCounts` 记录列表移除状态和历史清理位置。消息目前只追加，因此可以使用清理时的消息数量作为边界；后续若支持物理删除或重排消息，需要同时迁移该边界方案。

删除只更新当前角色的状态，不物理删除共享会话或对方消息。聊天页、摘要和列表排序均读取当前角色清理边界之后的消息。本人重新发起只恢复本人的入口；追加新消息恢复双方入口，双方原有清理边界保持不变。未读与不显示功能本次仅展示禁用按钮。

## 图片头像

角色使用可选的 `avatarData` 保存头像，不再保存矢量图标或颜色。创建与编辑角色复用系统相册选择器，导入时修正图片方向并生成最长边不超过 2048 的预览，在独立裁剪窗口中拖动及缩放，确认后按可见区域导出 512 × 512 的 JPEG；图片随角色数据一起保存在本地。列表、聊天和角色管理复用头像组件，无照片时显示灰底昵称首字。

旧数据中的 symbol、tint 字段解码时忽略，角色 ID 和聊天关联保持不变；旧角色可通过编辑入口设置新头像。选图取消或读取失败时保留原头像，未保存的编辑不写入本地。

## 个人资料

角色资料包含头像、名字和个性签名。资料页采用白底分行、右侧值与箭头的布局；头像使用相册选择，名字和签名单独编辑，资料页统一保存。编辑使用草稿，未保存时不修改角色或聊天记录。

签名随角色持久化，旧记录缺少该字段时默认为空。修改头像、名字或签名不改变角色 ID、当前身份和消息关联。

裁剪窗口使用原生 UIScrollView 处理缩放和平移，最小缩放始终填满方形裁剪框。取消不替换原头像，关闭后允许再次选择同一张照片。裁剪确认只更新资料草稿，资料保存后才持久化。裁剪坐标回归覆盖横图、竖图、居中、缩放和平移，并在模拟器核验导出像素与预览一致。
